        # 2️⃣ High-level PBFT flow

        PBFT has **three main phases** for consensus:

        1. **Pre-Prepare** – the leader proposes a value (e.g., a transaction or message)
        2. **Prepare** – all replicas vote that they received a valid proposal
        3. **Commit** – all replicas commit the value once enough votes are collected

        ---

        # 3️⃣ Mapping to your code structure

        | Component                | Role in PBFT                                                               |
        | ------------------------ | -------------------------------------------------------------------------- |
        | `PbftApplication.java`   | Bootstraps the Spring Boot node                                            |
        | `NodeConfig.java`        | Holds nodeId, port, and peers; helps other services know the environment   |
        | `NodeController.java`    | Exposes REST endpoints like `/preprepare`, `/prepare`, `/commit`           |
        | `Message.java`           | Model for messages exchanged between nodes (type, value, signatures, etc.) |
        | `CryptoService.java`     | Handles signing/verification of messages                                   |
        | `NodeClientService.java` | Sends messages to peer nodes (HTTP calls)                                  |
        | `ConsensusService.java`  | Tracks messages from peers and decides when consensus is reached           |

        ---

        # 4️⃣ Flow of execution (for 4 nodes)

        1. **Node startup**

        * Each node reads `application.properties`:

            * `server.port`
            * `node.id`
            * `peers` list
        * `PbftApplication` starts the embedded server (Tomcat)

        2. **Leader selection**

        * In a simple setup, node1 is the leader for the first round
        * Leader creates a **pre-prepare message** and signs it

        3. **Pre-Prepare Phase**

        * Leader calls `/preprepare` on all peers (via `NodeClientService`)
        * Each node receives the message in `NodeController` and validates the signature

        4. **Prepare Phase**

        * If valid, each replica broadcasts a **prepare message** to all other nodes
        * `ConsensusService` collects these prepare messages

        5. **Commit Phase**

        * Once a node receives **2f + 1 prepare messages** (f = max faulty nodes, for 4 nodes f=1)
        * Node broadcasts **commit message** to all nodes
        * Once a node receives **2f + 1 commit messages**, it commits the value

        6. **Consensus achieved**

        * All non-faulty nodes have the same committed value
        * PBFT round is complete

        # 6️⃣ Message flow example (simplified)

        ```
        Leader (node1)
            │ pre-prepare(value)
            ▼
        Node2, Node3, Node4
            │ prepare(value)
            ▼
        All nodes collect prepare messages
            │ commit(value)
            ▼
        All nodes commit the value
        ```

        * Each phase uses `Message.java` + `CryptoService`
        * Communication is handled by `NodeClientService` → calls REST endpoints in `NodeController`

        # 7️⃣ Key notes for your setup

        1. **Constant nodes** – yes, your current setup works best for a fixed number (4) because peers are hardcoded in `peers`
        2. **Leader rotation** – if you implement multiple rounds, you’ll rotate the leader (simple modulo by round number)
        3. **Fault tolerance** – PBFT can tolerate **f = (n-1)/3** faulty nodes → for 4 nodes, f = 1
